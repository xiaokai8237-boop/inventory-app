# 管理 APK 技术方案（物流筐 · 收款监听 + 老板管理）

> 方案日期：2026-08-12
> 状态：待用户拍板
> 基于：支付方案定案（经营码 + 监听自动开通）+ Phase 0 用户拍板项

## 一、目标与形态

**做独立的「物流筐管理 APP」（管理 APK）**，装在大哥手机上，承担两件事：

1. **收款监听**：用户扫码付钱 → 大哥手机收到"收款 12.81 元"通知 → 管理 APP 读到 → 上报云端 → 自动开通会员（微信+支付宝双通道，月流水 ≤1000 量级）
2. **老板管理**：用户统计 / 用户列表 / 重置密码 / 注销恢复 / 补发 VIP / 收款设置（云端可换码）/ 每日对账

**用户版 APP（员工装）完全不动**：管理页 11 项（店面/权限/模式/框名/备份/汇总/导出对账/建议/邀请/说明/安装）保留。

### 双 APP 分工

| | 用户版 APK（现有） | 管理 APK（新增） |
|---|---|---|
| 安装者 | 门店员工 | 大哥（老板） |
| 页面 | index.html（inventory-app-9ql.pages.dev） | admin.html（同一域名新页面） |
| 核心能力 | 记账/录入/汇总/会员中心/邀请 | 收款监听 + 用户管理 + 补发 + 收款设置 + 对账 |
| 登录 | 手机号+验证码 | 管理密码（首次记住，以后直接进） |
| appId | com.kuanwei.inventory | com.kuanwei.admin |
| 原生插件 | 无 | NotificationListenerService（通知监听） |

```
用户手机（员工/买家）                    大哥手机                      云端（Cloudflare Pages）
┌─────────────────┐   ┌──────────────────────────┐   ┌────────────────────────────┐
│ 用户版 APP       │   │ 管理 APK（com.kuanwei.admin）│   │ Pages Functions            │
│ 会员中心         │   │ ┌──────────────────────┐ │   │ /pay/order/create 下单      │
│ 点「开通月卡」    │──→│ admin.html（管理界面） │ │   │ /listen/report  监听上报     │
│ 显示收款码(尾数)  │   │ ├ 监听状态 / 用户管理  │ │   │ /admin/grant-vip 补发       │
│ 付完轮询看状态    │←──│ ├ 收款设置 / 补发VIP  │ │   │ /admin/stats 统计           │
└─────────────────┘   │ └ 每日对账            │ │   │ /admin/pay-config 收款配置  │
        │             │ ┌──────────────────────┐ │   │ /admin/reconcile 对账报告   │
        │ 扫码付款      │ │ 原生监听服务          │ │   └────────────────────────────┘
        ▼             │ │ NotificationListener │──→ 上报「收款 12.81」→ 匹配订单 → 开VIP
┌─────────────────┐   │ └──────────────────────┘ │
│ 微信/支付宝       │   │ （读大哥手机的收款通知，   │
│ 经营版收款码      │←──│   锁屏也工作）            │
└─────────────────┘   └──────────────────────────┘
   钱直接进大哥账户（经营码，合规）
```

**核心链路（8 步）**：
1. 用户点「开通月卡」→ 前端调 `/pay/order/create`（带尾数金额 12.81，防撞单）
2. 返回订单号 + 云端收款配置（当前生效的收款码图）
3. 用户扫码付款（金额 12.81 带尾数）→ 钱进大哥经营码
4. 大哥手机弹「收款 12.81 元」通知 → 管理 APK 原生监听服务读到
5. 上报 `/listen/report`（金额 + 时间 + listenKey + 设备ID）
6. 云端匹配未支付订单（金额一致）→ 标记已付 → 自动开通 VIP（月30/季90/年365/终身2100）
7. 用户端轮询 `/pay/status` → 弹「开通成功」
8. 大哥管理 APP 每日对账看流水

## 三、后端 API（新增/改动，全部在现有 Pages Functions）

| Method | Path | 功能 | 认证 | 说明 |
|---|---|---|---|---|
| POST | /pay/order/create | 创建监听支付订单 | 用户登录 token | 生成尾数金额订单，返回收款配置快照 |
| GET | /pay/status | 订单状态查询 | 用户 token + 订单归属 | 已有（支付宝方案），复用 |
| POST | /listen/report | 监听上报「收到 X 元」 | listenKey（管理端专属）| 匹配订单 → 发 VIP → 记流水 |
| POST | /listen/heartbeat | 监听心跳（在线状态） | listenKey | 管理 APP 每 5 分钟上报，管理页显示"监听在线/离线" |
| POST | /admin/stats | 注册统计 + 用户列表 + 待恢复 | adminKey | 已有，扩展字段 |
| POST | /admin/reset-password | 重置用户密码 | adminKey | 已有 |
| POST | /admin/restore-account | 恢复注销账号 | adminKey | 已有 |
| POST | /admin/grant-vip | 补发 VIP（手机号+档位/天数） | adminKey | 第 5 层兜底 |
| GET | /admin/pay-config | 读收款配置 | adminKey | 微信码/支付宝码/客服码/微信号/客服时间 |
| POST | /admin/pay-config/save | 存收款配置 | adminKey | 图片 base64 存 KV（≤1MB），全局生效 |
| GET | /admin/reconcile | 每日对账报告 | adminKey | 收到N / 匹配M / 未匹配K + 明细 |
| GET | /admin/flow | 收款流水查询 | adminKey | 按日期/状态筛选 |
| GET | /pay/order/config | 用户端拉收款配置（公共） | 无 | 下单页展示收款码用（仅码图+订单号，无敏感信息） |

**KV 键设计**（BACKUP_KV 复用）：
- `pay_order_{orderNo}`：订单（orderNo/phone/planId/amount/status/createdAt/paidAt）
- `pay_flow_{date}_{seq}`：收款流水（amount/time/source:listen/orderNo 关联/status）
- `pay_config`：收款配置 JSON（wxQr/alipayQr/kfQr/kfWx/kfHours）
- `listen_devices`：管理设备注册表（deviceId → listenKey 前缀）
- `reconcile_{date}`：每日对账快照（收到/匹配/未匹配 + 明细索引）

## 五、监听插件设计（原生，唯一 APK 新增部分）

**技术**：Android `NotificationListenerService`（官方 API，免 ROOT，锁屏可用）

```
class PayNotificationListener : NotificationListenerService() {
  onNotificationPosted() {
    读取通知标题/文本
    匹配「收款」/「到账」+ 金额正则（如 12.81）
    若是微信/支付宝收款通知 → 组装 {amount, time} → 通过 Capacitor 事件桥接给 WebView
  }
}
```

**关键点**：
1. **通知解析**：微信「微信支付收款 12.81 元」/ 支付宝「到账 12.81 元」两种文案正则；金额取第一个匹配数字
2. **权限引导**：Android 13+ 通知监听需用户手动开启（设置页内嵌跳转 + 3 步图文引导：①锁屏显示通知详情 ②电池白名单 ③通知权限）
3. **上报安全**：`listenKey`（管理 APP 首启从管理密码派生，注册设备）——防止任何人伪造"收款上报"刷 VIP
4. **防重复**：同一金额 5 分钟内去重（防微信双端通知重复上报）
5. **失败兜底**：上报失败重试 3 次（指数退避）；连续失败标记监听"异常"提示大哥检查
6. **心跳**：每 5 分钟 `/listen/heartbeat`，管理页显示在线状态；超过 15 分钟无心跳 → 管理页红色告警

**Capacitor 插件方式**：在管理 APK 的 android 工程内写自定义 plugin（`com.kuanwei.admin.PayListenerPlugin`），bridge 事件 `onPayReceived` 推给 WebView（admin.html 的 JS 监听并上报云端）。无需发布到 npm，本地工程内嵌。

## 六、撞单与匹配策略

| 场景 | 策略 |
|---|---|
| 两人同时付 12.8 | 下单时若存在未支付同额订单 → 新订单金额 +0.01 尾数（12.81/12.82），金额唯一 |
| 用户付错金额 | 匹配失败 → 流水记"未匹配"→ 对账报告列出 → 大哥人工补发 |
| 重复上报 | 同一订单号只发一次 VIP（幂等，订单状态 created→paid 原子切换） |
| 通知延迟 | 最长半小时（系统通知本身延迟）→ 用户端状态"已支付待确认"安抚 |
| 漏单 | 第 1 层客服卡片（微信码 + 复制号 + 工作时间 01:00-15:00）→ 微信人工 → 补发 VIP |

## 八、收款配置云端化（用户已拍板）

- 码不写死在 APP：管理 APP「收款设置」上传新码 → 存 KV → 用户端下单页实时拉取当前生效码
- 可随时换：收款码失效 / 换账户 / 客服换号 / 改客服时间 → 30 秒生效，不用重新打包
- 图片限制：单张 ≤1MB（base64 存 KV），首次上传自动压缩

## 十一、风险与对策

| 风险 | 对策 |
|---|---|
| 手机系统杀后台导致漏单 | 3 步白名单设置 + 心跳告警（15 分钟无心跳红警）+ 每日对账兜底 |
