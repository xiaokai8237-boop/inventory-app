## 二、关键核实：用户已开通的"经营版收款"能力对照（2026-08-11 调研结论）

> 用户已开通微信 + 支付宝"经营版收款"。但**"经营版收款"≠"可自动开通的支付接口"**，必须分清：

| 已开通的东西 | 有没有 API 接口 | 能不能自动回调到账 | 结论 |
|--------------|-----------------|-------------------|------|
| 微信「经营收款码」/「商家收款码」（扫收款码转账） | ❌ 无 API | ❌ 无回调，只能手动看收款记录 | **不能**用于自动开通 |
| 微信支付「商户号」Native/JSAPI 支付 | ✅ 有 API | ✅ 支付成功回调 notify_url | **能**自动开通 |
| 支付宝「商家收款码」（静态码） | ❌ 无 API | ❌ 无回调 | **不能**用于自动开通 |
| 支付宝「当面付/手机网站支付」（开放平台签约） | ✅ 有 API | ✅ 异步通知 notify_url | **能**自动开通 |

> **结论：用户现有的"经营版收款"大概率是收款码（无 API），方案 B 自动开通需要另走正规商户通道（微信商户号 / 支付宝当面付签约）。这不是"重开"，而是在现有收款基础上补 API 能力。**

## 四、技术方案选型（v4：易支付类聚合支付为主）

### 用户拍板形态
**H5 网页支付 + 易支付类聚合通道**：用户在 APP 会员中心点「立即开通」→ 后端调易支付下单接口 → 返回跳转 URL → 唤起微信/支付宝 → 付完自动跳回 APP → 异步回调自动开通 VIP。免签约、免执照、免备案，注册即用，费率约 1%。

### 方案对比

| 方案 | 门槛 | 手续费 | 自动开通 | 风险 | 结论 |
|------|------|--------|----------|------|------|
| **A. 易支付类聚合（主通道，用户拍板）** | ✅ 免费注册，个人免签约 | ~1% | ✅ 异步回调 | 平台跑路/通道关停（需防跑路策略） | **推荐**：最快上线 |
| B. 支付宝手机网站支付（官方） | 需备案域名 | 0.6% | ✅ | 低 | 后补降本 |
| C. 微信 H5 支付（官方） | 认证服务号300元/年+执照+备案+类目 | 0.6% | ✅ | 低 | 后补（资质最重） |
| D. XPay 免签 | 免费 | 0 | ❌ 人工审核（邮件点确认） | 个人码做经营封号/冻钱 | ❌ 已否决 |
| E. 收款码+监听挂机 | 免费 | ~0.1% | 半自动（需挂机设备） | 不稳定/风控 | ❌ 不推荐 |

### 易支付类平台核心机制（彩虹易支付兼容协议）

```
用户选档位 → 点「立即开通」
    ↓
前端 POST /api/pay/create  {phone, planId, deviceId}
    ↓
云函数: 校验登录 + 生成订单号 + 调易支付下单接口
       (pid/type=alipay|wxpay/out_trade_no/notify_url/return_url/name/money/sign MD5或RSA)
    ↓
返回: pay_type=jump + pay_info=支付跳转URL（如 weixin://wxpay/bizpayurl?pr=xxx 或支付宝收银台）
    ↓
前端跳转 pay_info → 唤起微信/支付宝 → 用户支付
    ↓
支付完成 → 易支付 POST 异步回调 /api/pay/notify（MD5/RSA 验签 + 幂等 + 返回 success）
    ↓
云函数: 给该账号 vipUntil += 对应天数（终身=2100年）→ 写 account_
    ↓
return_url 同步跳回 → 前端轮询 /api/pay/status {orderNo} → 成功 → 弹「开通成功」→ 刷新会员中心
```

**关键设计点（聚合支付专属）**：
| 点 | 设计 |
|----|------|
| 验签 | 易支付回调必须校验签名（MD5 或 RSA，按平台协议），防止伪造回调刷 VIP |
| 幂等 | 回调幂等（同一订单只加一次 VIP，用订单号去重） |
| 金额校验 | 回调金额必须与订单金额一致（防改价刷单） |
| 回调响应 | 验签通过后必须原样返回 `success`，否则平台重试/丢单 |
| return_url vs notify_url | return_url 只做前端展示，notify_url 异步回调唯一可信 |
| 订单过期 | 订单 2 小时有效，超时取消 |
| 会员叠加 | 已 VIP 用户续费 = 在原 vipUntil 基础上加天数（不是重置） |
| 终身卡 | vipUntil 设 2100-12-31（或加 isLifetime 标记） |
| 防跑路 | 选 D0 实时结算平台 + 每日提现，资金不在平台过夜 |
| APP 跳回 | WebView 唤起支付宝/微信后回跳 return_url：需真机验证（P-6） |

### 数据存储（沿用现有 KV）

| KV key | 内容 |
|--------|------|
| `pay_order_<orderNo>` | 订单：phone/planId/amount/status(created/paid/closed)/createdAt/paidAt |
| `account_<phone>.vipUntil` | 已存在，续费时叠加 |

### 前端改动点

1. 会员中心「立即开通」→ 调支付（替换现在 toast）
2. 新增支付弹窗/页面：二维码展示 + 轮询状态 + 成功/失败/过期三态
3. VIP_TEST_MODE=false 开关（正式收费时切，7 处拦截自动生效）

## 四、老用户政策（测试期 → 正式收费过渡）

**这是最容易得罪人的环节，建议二选一（或组合）：**

| 方案 | 内容 | 优缺点 |
|------|------|--------|
| **方案 1：老用户赠期** | 测试期注册的用户，正式收费后**自动送 1 个月 VIP**（按注册时间） | 好口碑；成本低（1 个月） |
| **方案 2：老用户感恩价** | 首月 0.1 元 / 年卡 5 折（限测试期老账号） | 有收入又有诚意 |
| **方案 3：邀请抵扣** | 正式收费时，之前邀请成功的每个好友 = 减 5 元（已有邀请记录数据） | 拉新和收费联动，最有增长价值 |

> 我的建议：**方案 1 + 3 组合**——老用户送 1 个月 + 邀请记录折现，既安抚老用户又激励拉新。

## 七、风险与对策

| 风险 | 对策 |
|------|------|
| 聚合平台跑路（无牌照，钱卡在平台） | **选 D0 实时结算平台 + 每日提现，资金不过夜**；小额测试期跑 1-2 周确认稳定再正式推 |
| 聚合通道被微信/支付宝风控关停 | 备选 2-3 家平台（同协议可无缝切换）；官方通道（支付宝/微信）作为长期降本方案后补 |
| 回调伪造/刷 VIP | 回调严格验签（MD5/RSA）+ 金额与订单一致校验 + 订单号幂等 |
| 回调丢单 | 前端轮询兜底 + 每日对账脚本（拉取平台账单比对订单状态） |
| 用户支付后 VIP 没到账 | 回调幂等 + 前端「我已支付未到账」申诉入口（管理员手动补发） |
| 营业执照两年没营业（官方通道后补时用） | 先查执照状态（国家企业信用信息公示系统）；经营异常→补年报免费恢复；已吊销→重办个体户执照 |
| 备案域名等待期（官方通道后补时用） | 提交备案后开发并行；聚合通道先收款不阻塞 |

## 八、结论

- **支付形态（v3 用户拍板）**：H5 网页支付——点开通 → 跳转浏览器/微信/支付宝 → 付完自动回 APP，不做 APP 原生支付（纯网页实现，无需原生 SDK）
- **主通道（v4 用户拍板）**：**易支付类聚合支付**——免费注册、个人免签约、无执照/备案门槛、费率约 1%、异步回调自动开通，**3-5 天可上线收款**
- **防跑路铁律**：选 D0 实时结算平台 + 每日提现，资金不过夜；备选 2-3 家同协议平台可无缝切换
- **降本优化（后补）**：备案域名 + 支付宝官方手机网站支付（0.6%）→ 微信官方 H5（0.6%），替换聚合通道省一半手续费；官方通道需有效执照 + 备案域名（1-2 周等待）
- **过渡期**：保持测试期免费跑通拉新，正式收费用「老用户送 1 月 + 邀请折现」平滑过渡
- **前端改动**：会员中心「立即开通」→ 支付跳转（H5）+ 轮询 + 三态 + VIP_TEST_MODE 开关切换，改动量约 1 天；**P-6 APP 跳回需真机验证**（Capacitor WebView 唤起支付宝/微信后回跳 return_url）
