## 二、关键核实：用户已开通的"经营版收款"能力对照（2026-08-11 调研结论）

> 用户已开通微信 + 支付宝"经营版收款"。但**"经营版收款"≠"可自动开通的支付接口"**，必须分清：

| 已开通的东西 | 有没有 API 接口 | 能不能自动回调到账 | 结论 |
|--------------|-----------------|-------------------|------|
| 微信「经营收款码」/「商家收款码」（扫收款码转账） | ❌ 无 API | ❌ 无回调，只能手动看收款记录 | **不能**用于自动开通 |
| 微信支付「商户号」Native/JSAPI 支付 | ✅ 有 API | ✅ 支付成功回调 notify_url | **能**自动开通 |
| 支付宝「商家收款码」（静态码） | ❌ 无 API | ❌ 无回调 | **不能**用于自动开通 |
| 支付宝「当面付/手机网站支付」（开放平台签约） | ✅ 有 API | ✅ 异步通知 notify_url | **能**自动开通 |

> **结论：用户现有的"经营版收款"大概率是收款码（无 API），方案 B 自动开通需要另走正规商户通道（微信商户号 / 支付宝当面付签约）。这不是"重开"，而是在现有收款基础上补 API 能力。**

## 三、前置条件（必须先解决，否则支付接不上）

| # | 条件 | 说明 | 状态 |
|---|------|------|------|
| P-1 | **微信支付商户号** | 需个体工商户营业执照（用户已有，但两年多没营业——**需先确认执照状态**：被吊销/注销则不可用，经营异常可补年报恢复）+ 法人身份证。费率 0.6%。**关联需微信认证小程序/服务号（认证费 300 元/年）** | ⛔ 待办 |
| P-2 | **支付宝当面付签约** | 个人/个体户可开通，需营业执照或经营场所照片（无执照额度受限：单笔 ≤2000 / 单日 ≤20000；个体户执照额度高）。费率 0.6%。**个人开发者可先走通** | ⛔ 待办 |
| P-3 | **备案域名** | 微信 Native 回调 + 支付宝 notify_url **都必须用已 ICP 备案的 HTTPS 域名**（2026 年未备案拦截率极高）。pages.dev 无法备案 → 需注册备案域名（约 60 元/年 + 备案 1-2 周） | ⛔ 未办 |
| P-4 | **商户证书/密钥** | 微信 API v3 密钥 + 商户私钥证书（申请商户号后生成） | ⛔ 未办 |
| P-5 | **收款结算账户** | 微信个体户可结算到法人个人银行卡（无需对公账户）；支付宝结算到支付宝余额 | ⛔ 待办 |

> **结论：P-1/P-2（支付通道）+ P-3（备案域名）是硬门槛。备案域名 1-2 周等待期最长，建议最先启动；支付宝当面付个人可先通，微信商户号后补。**

## 四、技术方案选型

### 方案对比（基于 Cloudflare Pages Functions 无服务器架构）

| 方案 | 支付方式 | 用户体验 | 技术复杂度 | 资质门槛 | 适配场景 |
|------|----------|----------|-----------|----------|----------|
| **A1. 微信 Native 扫码（推荐主通道）** | 网页显示二维码，手机微信扫 | 扫码→微信内确认→支付 | 中（无 openid 要求） | 高：需商户号+备案域名+认证 | 手机网页/电脑端都能用，无需公众号 |
| **A2. 支付宝当面付（推荐先通）** | 网页显示二维码，支付宝扫 | 扫码→支付宝内确认→支付 | 中 | 低：个人可签，有执照额度高 | 个人开发者最快落地，可先行 |
| B. 微信 JSAPI | 微信内直接拉起支付 | 最顺滑 | 高（需公众号+openid） | 高 | 需公众号，暂不适用 |
| C. 支付宝手机网站支付 | 跳转支付宝收银台 | 好 | 中 | 低 | 可作补充 |
| D. 第三方聚合（虎皮椒/易支付等） | 封装微信/支付宝 | 一般 | 低 | 低（但有跑路/风控风险） | 过渡可选，费率偏高（1-2%） |

**推荐：A2 支付宝当面付先行（个人可签、最快跑通）+ A1 微信 Native 后补（用户微信使用率高，必须做）**。
不推荐 D（第三方聚合）作为正式方案——资金安全和稳定性风险，仅作备案域名等待期的临时过渡可考虑。

### 订单流程（以支付宝当面付为例，微信 Native 同构）

```
用户选档位(月/季/年/终身) → 点「立即开通」
    ↓
前端 POST /api/pay/create  {phone, planId, deviceId}
    ↓
云函数: 校验登录 + 生成订单号 + 调支付宝预下单API(金额/商品名/notify_url)
    ↓
返回: 二维码内容(qr_code) + 订单号
    ↓
前端展示二维码 + 「支付宝扫一扫支付」+ 支付倒计时
    ↓
支付完成 → 支付宝异步通知 POST /api/pay/notify（云函数验签+幂等）
    ↓
云函数: 给该账号 vipUntil += 对应天数（终身=2100年）→ 写 account_ 
    ↓
前端轮询 /api/pay/status {orderNo} → 成功 → 弹「开通成功」→ 刷新会员中心
```

### 关键设计点

| 点 | 设计 |
|----|------|
| 幂等 | 支付回调幂等（同一订单只加一次 VIP，用订单号去重） |
| 防刷 | 下单前校验登录 + 档位金额与商品ID一一对应（防止改价） |
| 回调安全 | 微信验签（API v3 用平台证书验签）+ 回调地址白名单 |
| 订单过期 | 二维码 2 小时有效，超时取消 |
| 会员叠加 | 已 VIP 用户续费 = 在原 vipUntil 基础上加天数（不是重置） |
| 终身卡 | vipUntil 设 2100-12-31（或加 isLifetime 标记） |
| 退款 | 暂不做在线退款（个人主体可先说明"联系管理员人工处理"） |

### 数据存储（沿用现有 KV）

| KV key | 内容 |
|--------|------|
| `pay_order_<orderNo>` | 订单：phone/planId/amount/status(created/paid/closed)/createdAt/paidAt |
| `account_<phone>.vipUntil` | 已存在，续费时叠加 |

### 前端改动点

1. 会员中心「立即开通」→ 调支付（替换现在 toast）
2. 新增支付弹窗/页面：二维码展示 + 轮询状态 + 成功/失败/过期三态
3. VIP_TEST_MODE=false 开关（正式收费时切，7 处拦截自动生效）

## 四、老用户政策（测试期 → 正式收费过渡）

**这是最容易得罪人的环节，建议二选一（或组合）：**

| 方案 | 内容 | 优缺点 |
|------|------|--------|
| **方案 1：老用户赠期** | 测试期注册的用户，正式收费后**自动送 1 个月 VIP**（按注册时间） | 好口碑；成本低（1 个月） |
| **方案 2：老用户感恩价** | 首月 0.1 元 / 年卡 5 折（限测试期老账号） | 有收入又有诚意 |
| **方案 3：邀请抵扣** | 正式收费时，之前邀请成功的每个好友 = 减 5 元（已有邀请记录数据） | 拉新和收费联动，最有增长价值 |

> 我的建议：**方案 1 + 3 组合**——老用户送 1 个月 + 邀请记录折现，既安抚老用户又激励拉新。

## 六、实施步骤（预计 3-5 天开发 + 等待资质，双通道分阶段）

| 步骤 | 内容 | 依赖 | 时长 |
|------|------|------|------|
| 0 | **立即启动：确认营业执照状态**（手机微信搜「国家企业信用信息公示系统」小程序查执照是否存续；被列异常→补年报恢复；已吊销→需重办执照或走小微/个人路线） | — | 1 天 |
| 1 | **注册备案域名 + 提交 ICP 备案**（约 60 元/年，阿里云/腾讯云均可，与 APP 部署域名共用） | — | 1-2 周（等待） |
| 2 | **支付宝当面付签约**（个人/个体户，开放平台创建应用+签约当面付，拿 APPID/密钥；有执照额度高） | 步骤 0 | 1-3 天（审核） |
| 3 | 域名解析到 Cloudflare + 支付回调子域（pay.域名.com）+ 迁移部署 | 步骤 1 | 半天 |
| 4 | **后端支付云函数**：下单/回调/查询 + 验签 + 幂等 + 防刷（支付宝通道） | 步骤 2 的密钥 | 1-2 天 |
| 5 | **前端会员中心接入**：支付弹窗（二维码/轮询/成功/失败/过期三态） | 步骤 4 | 1 天 |
| 6 | 测试：真机支付全流程（支付宝一单）→ **支付宝通道上线** | 步骤 4-5 | 半天 |
| 7 | **微信支付商户号申请**（需有效执照 + 认证小程序 300 元/年）→ Native 支付 + 回调 | 步骤 0 | 3-7 天（审核） |
| 8 | 后端接微信通道（下单/回调/验签）→ 前端支付弹窗加「微信/支付宝」双 Tab | 步骤 7 | 1 天 |
| 9 | VIP_TEST_MODE=true → false 切换 + 老用户政策生效 | 全部 | 0.5 天 |
| 10 | 上线监控（支付成功率/回调失败率/丢单告警） | — | 持续 |

> **节奏建议：步骤 0-6 支付宝通道 2 周内可上线（含备案等待）；微信通道在支付宝跑通后补做。备案域名等待期不阻塞开发（可用沙箱联调）。**

## 七、风险与对策

| 风险 | 对策 |
|------|------|
| 营业执照两年没营业 → 被吊销/经营异常，微信商户号申请被拒 | ①先查执照状态（国家企业信用信息公示系统）；②经营异常→补年报免费恢复；③已吊销→重办个体户执照（线上 3 天，约 0 元）或支付宝先走个人当面付额度（单笔≤2000） |
| 备案等待期长（1-2 周） | 提交备案后立即用支付宝沙箱联调 + 前端支付弹窗开发并行；备案下来即切换正式环境 |
| 微信认证费 300 元/年（需关联小程序/服务号） | 属微信硬性要求，接受；或先用支付宝通道收款，微信通道评估后再开 |
| 支付回调丢单 | 前端轮询兜底 + 每日对账脚本（拉取支付宝/微信账单比对订单状态） |
| 用户支付后 VIP 没到账 | 回调幂等 + 前端「我已支付未到账」申诉入口（管理员手动补发） |
| 用户扫码习惯不同（有人只认微信） | 双通道并行：支付宝先上，微信后补；测试期免费过渡不造成付费流失 |

## 八、结论

- **用户已有的"经营版收款"（收款码）无 API，不能直接自动开通**；方案 B 需补正规商户通道：**支付宝当面付（个人可签、最快）+ 微信 Native（需有效执照 + 备案域名 + 认证）**
- **最大瓶颈不是技术，是资质**：备案域名（1-2 周）+ 营业执照状态（需确认/恢复）
- **建议**：①今天就去查执照状态（决定微信通道可行性）；②立即注册备案域名提交备案；③支付宝当面付签约 → 2 周内支付宝通道上线；④微信通道后补 → 双通道齐备
- **过渡期**：保持测试期免费跑通拉新，正式收费用「老用户送 1 月 + 邀请折现」平滑过渡
- **前端改动**：会员中心「立即开通」→ 支付弹窗（二维码 + 轮询 + 三态）+ VIP_TEST_MODE 开关切换，改动量约 1 天
